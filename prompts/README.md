# Build prompts

The exact prompts that built this system. Not how-to-use guides. Not generic templates. Each file is one prompt that produced one specific deliverable when given to an AI agent (Cursor or Claude Code).

Run them in order on a fresh repo with a Jira project, GitHub repo, and Claude Code OAuth token already configured, and you reproduce The Dark Factory.

## The recipe

| Step | Prompt | Produces |
|---|---|---|
| 1 | [`01-build-dispatch-flow.md`](01-build-dispatch-flow.md) | `.github/workflows/jira-dispatch.yml` + `.github/scripts/jira-dispatch.mjs` (modes: `prepare-dispatch`, `record-run`, `commit-changes`, `ensure-pr`, `comment-result`) + `CLAUDE.md` |
| 2 | [`02-build-in-progress-transition.md`](02-build-in-progress-transition.md) | `transitionToInProgress` helper called from `prepare-dispatch` |
| 3 | [`03-build-pr-merged-finalize.md`](03-build-pr-merged-finalize.md) | `.github/workflows/jira-pr-merged.yml` + `transition-done` mode |
| 4 | [`04-build-architecture-doc.md`](04-build-architecture-doc.md) | `architecture.md` (six progressive depths, full diagrams, cold-start rebuild data) |
| 5 | [`05-build-installer-skill.md`](05-build-installer-skill.md) | `skills/dark-factory-installer/SKILL.md` (runbook the agent executes inline, no driver scripts) |

## Order matters

Each step depends on the previous step's deliverable. Step 2 modifies the script written in step 1. Step 3 references the workflow architecture from step 1. Step 4 documents what was built in steps 1–3. Step 5 packages it for redistribution.

If you skip step 1 and try step 2, the agent has nothing to extend. If you do steps 1–3 but skip 4 and 5, you have a working orchestrator but nothing self-replicating.

## Things deliberately NOT in this folder

- Generic ticket templates ("how to write a `claude:answer` ticket"). They live in the worked examples inside `architecture.md` and the SKILL.
- The runtime system prompt sent to Claude on every dispatch. That's generated by `buildPrompt()` in `jira-dispatch.mjs`. The script itself is the source of truth.
- The Jira automation rule body. Documented inline in `architecture.md` §5 and in the SKILL step 5.
- "How to install" instructions for end users. That's the SKILL itself plus its install one-liner — not a build prompt.

These exist elsewhere, on purpose. This folder is the *build recipe*, nothing more.
